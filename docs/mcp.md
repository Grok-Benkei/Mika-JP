# MCPでMika JPへ接続する

[PCからの利用](computer.md) · [CLIとスキル](cli.md)

コンピューターアクセスを有効にすると、Mika JPをMCPサーバーとして使えます。PCのMCPクライアントが目的を渡し、スマホ上のMika JPがアプリ、内蔵ブラウザ、ファイル処理を使って実行し、結果を返します。

スマホ側の導入は[Mika JPの導入](setup-guide.ja.md)を参照してください。上流MikaのAPKではなく、このフォークのAPKを使います。

接続には、別々のスイッチとトークンを持つ二つの方法があります。併用もできます。

- USB: ADB転送でスマホのローカルポートへ接続します。Wi-Fi側には公開しません。
- Wi-Fi・プライベートVPN: スマホでネットワークアクセスを有効にし、同じプライベートネットワークから接続します。ルーターのポート公開は不要です。

## USBで接続する

PCにAndroid platform-toolsがあり、対象が `adb devices` に `device` と表示され、Mika JPを一度開いていることが前提です。複数端末がある場合は、以下のadbコマンドすべてに `-s SERIAL` を付けて同じ端末を指定します。

1. コンピューターアクセスを有効にします。

   ```sh
   adb shell sh /sdcard/Android/data/jp.studioyebisu.mika/files/connect-computer.sh
   ```

   必要ならスマホ操作ヘルパーも起動し、USB接続を有効にして接続情報を返します。次は形式の例で、`<TOKEN>` は実際のトークンに置き換わります。出力には秘密値が含まれるため、チャットや共有ログへ貼り付けないでください。

   ```json
   {
     "transport": "streamable-http",
     "url": "http://127.0.0.1:8765/mcp",
     "headers": { "Authorization": "Bearer <TOKEN>" },
     "token": "<TOKEN>",
     "port": 8765,
     "forward": "adb forward tcp:8765 tcp:8765",
     "boot": "17"
   }
   ```

2. PCのポートをスマホへ転送します。

   ```sh
   adb forward tcp:8765 tcp:8765
   ```

3. MCPクライアントにStreamable HTTP（クライアントによってはHTTP）型のサーバーを追加します。URLは `http://127.0.0.1:8765/mcp`、ヘッダーは `Authorization: Bearer <TOKEN>` です。設定形式は後述の例を参考に、使用するクライアントの形式へ合わせてください。
4. クライアントを接続、またはツール一覧を更新し、スマホ側にPCからの要求時刻が表示されることを確認します。接続だけではタスクは実行されません。

接続情報は `/sdcard/Android/data/jp.studioyebisu.mika/files/mcp-usb.json` に保存されます。必要な場合は、本人のPC上でのみ扱い、トークンを報告へ含めないでください。

有効な間はスマホに通知が表示され、アプリが背景でも待ち受けます。接続前の表示と、要求を受け取った後の表示は別です。

- ケーブルの抜き差しやPC側adbの再起動後は、転送コマンドを再実行します。トークンは変わりません。
- 有効な状態で起動スクリプトを再実行しても、トークンは保持します。
- スマホの再起動でUSBアクセスは無効になります。スクリプトを再実行し、新しいトークンをクライアントへ設定します。

無効にする場合は次を使います。

```sh
adb shell sh /sdcard/Android/data/jp.studioyebisu.mika/files/connect-computer.sh off
```

スマホの詳細設定でUSB接続を無効にする方法もあります。通知の停止操作は、有効になっているネットワーク接続も停止します。無効にすると古いトークンは直ちに無効になり、USBの接続情報ファイルを削除します。次回は新しいトークンです。

起動スクリプトを使わずサービスへ直接指示する場合のコンポーネントとアクションは次のとおりです。接続情報ファイルの作成には少し時間がかかります。

```sh
adb shell am start-foreground-service -n jp.studioyebisu.mika/com.wangzan101.mika.mcp.McpService -a com.wangzan101.mika.mcp.USB_ON
adb shell am start-foreground-service -n jp.studioyebisu.mika/com.wangzan101.mika.mcp.McpService -a com.wangzan101.mika.mcp.USB_OFF
```

アプリIDは `jp.studioyebisu.mika` ですが、クラス名とアクション名の `com.wangzan101.mika` は保持します。

## Wi-Fi・プライベートVPNで接続する

スマホの「設定 › コンピューターに接続」でMCPとWi-Fi／VPNを選び、ネットワークアクセスを有効にします。案内の表示や接続方法の選択だけでは有効になりません。既定は無効です。

PCから到達できるアドレスを選び、設定をコピーしてクライアントへ登録します。コピーした設定にはアドレスとトークンが含まれます。プレビューは既定で折りたたまれ、表示を開いてもトークンは伏せられます。トークンのコピー・変更、接続スイッチ、遠隔起動・ロック解除は詳細設定にあります。

CLIとスキルも同じ接続方法の選択を共有しますが、CLIはHTTPのルートURLとトークンファイルを使うため、MCP設定は不要です。

同じWi-Fiなら通常は `192.168.*.*` や `10.*.*.*` のアドレス、プライベートVPNならそのネットワークのアドレスを使います。VPNでは `100.64.*.*` 〜 `100.127.*.*` が使われることもあります。スマホがモバイルデータだけを使っている場合や、接続元が公開IPの場合は、直接接続を受け付けません。

設定例は次のとおりです。アドレスとトークンは本人のものに置き換えます。

```json
{
  "mcpServers": {
    "mika": {
      "type": "http",
      "url": "http://192.168.1.23:8765/mcp",
      "headers": { "Authorization": "Bearer <TOKEN>" }
    }
  }
}
```

初期化だけを確かめる要求の例です。タスクは開始しません。実際のトークンをシェルの履歴や共有ログに残さないよう、保存方法は使用するクライアントの機能に合わせてください。

```sh
curl -s http://192.168.1.23:8765/mcp \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

トークンはスマホ内に暗号化して保存します。ネットワークアクセスを無効にすると、外部向けの待受を停止します。USBが有効ならスマホ内のローカル待受だけが残ります。

## セルフホストのリモート接続

公開ネットワーク越しに使う場合は、任意でゲートウェイを自分で運用できます。スマホのリモート接続画面でペア設定し、明示的にアクセスを有効にして、Authorizationヘッダーへ対応したクライアントへHTTPS設定を登録します。スマホからゲートウェイへ接続するため、同じWi-FiやVPNは不要です。

CLI・スキルも同じゲートウェイを使えます。認証はスマホがLAN用アクセストークンで行い、ゲートウェイはペア設定と転送を担当します。アクセストークンの管理やOAuth認証は提供しません。初版は一人・一台向けです。リレーのウェブ画面は日本語で表示します。

導入は[リモートCLI／MCP](dev/remote-mcp.md)を参照してください。ゲートウェイはHTTPSを終端し、転送内容を読めます。信頼できる運用先だけを使ってください。

## タスクのツール

| ツール | 引数 | 動作 |
| --- | --- | --- |
| `mika_run_task` | goal必須、conversation・request_idは任意 | 依頼を渡し、task_idを返す。続きを頼む場合は前のconversationを渡す |
| `mika_task_status` | task_id | 現在の状態、最新進捗、待機理由、終了時の回答を読む |
| `mika_wait_task` | task_id、任意のtimeout_s（既定30、最大50） | 状態変化か時間切れまで待ち、状態を返す。進捗文の変化だけでは戻らない |
| `mika_answer` | task_id、text | そのタスクが尋ねた質問へ回答する |
| `mika_steer_task` | task_id、text（最大4000文字） | 実行中のタスクへ追加指示を届け、acceptedとmessage_idを返す |
| `mika_cancel_task` | task_id | 停止を要求する |
| `mika_list_tasks` | 任意のlimit（既定10） | PCから渡した最近のタスクを新しい順に読む |

タスクはスマホの会話一覧にも記録されます。状態は次のとおりです。

| 状態 | 意味 |
| --- | --- |
| `starting` | スマホへ渡した直後で、開始前 |
| `running` | 実行中 |
| `queued` | 同時実行数や同じ会話の先行タスクを待っている。順番が来ると開始する |
| `paused` | ロック解除などの条件待ち。条件が整うと再開する |
| `waiting_for_answer` | 質問への回答待ち。mika_answerまたはスマホで回答する。時間切れは未回答として処理し、同意や回答とは扱わない |
| `waiting_on_phone` | 本人がスマホで対応する段階。PCからは待機か停止だけができる |
| `done` | 回答を返して終了。verifiedは検証情報で、値がなければ不明 |
| `failed` | 未完了。理由を確認する |
| `cancelled` | 停止済み |

基本の流れは、`mika_run_task` → `mika_wait_task` を繰り返す → 質問待ちなら `mika_answer` → `done`・`failed`・`cancelled` の確認です。停止要求を受理しただけでは停止済みと報告しません。

入力スキーマに `request_id` がある場合は、送信前に小文字のUUIDを保存すると、応答を失っても同じIDで照会できます。同じID・依頼・会話は一度だけ開始します。異なる依頼には新しいIDを使ってください。プロセス再起動後も終了済みの結果を取得でき、途中だったタスクは `failed`、`failure_kind=interrupted` になります。終了記録は30日間、最大直近1000件です。詳しい回復条件は[CLIの説明](cli.md#応答を失ったタスクを確認する)を参照してください。

追加指示は `running` にだけ送れます。`steers` の該当 `message_id` を確認すると、`received` は受信済みで取り込み待ち、`joined` は文脈への取り込み、`not_applied` は終了まで未使用を意味します。取り込みは実行成功を証明しません。実行中の操作が先に終わり、過去の操作を取り消すこともありません。

待ち行列・一時停止・質問や承認や引き継ぎの待機中・終了済みには追加できません。終了との競合で別タスクを始めることもありません。応答が失われても自動で再送せず、元のタスクを確認します。`mika_steer_task` が一覧にない場合は、対応するMika JPへ更新してください。

## 遠隔で画面を点灯・ロック解除する

この機能は任意で、既定では無効です。スマホのコンピューター接続の詳細設定から本人が許可します。ゲートウェイ経由の場合は、リモート接続画面でもゲートウェイからの起動・ロック解除を許可する必要があります。許可がなければ、以下のツールはクライアントへ提示されません。

スワイプだけの画面ロックは認証情報の保存が不要です。PIN・パスワードを使う場合は、スマホ上で現在の値を2回入力して保存します。PCは保存や読み取りをできません。

| ツール | 引数 | 動作 |
| --- | --- | --- |
| `mika_device_state` | なし | 画面、画面ロック、ヘルパー、許可状態を読む |
| `mika_wake_device` | なし | メイン画面を点灯する。認証はしない |
| `mika_unlock_device` | なし | 点灯し、スワイプのロックを解除するか、スマホ内に保存した認証情報で解除する |

タスクを始める前に解除する場合は、`status: unlocked` と `device.ready: true` を確認します。`awake` は点灯しただけで、解除の証拠ではありません。解除待ちの既存タスクは、Androidが解除を確認すると自動で再開します。

- PINは4〜16桁、パスワードは4〜64文字の印字可能なASCII文字に対応します。パターン、SIM PIN、認識できないメーカー独自の認証画面には入力せず、`unsupported_keyguard` を返します。
- PIN・パスワードの入力はAndroid 13以降です。システムのロック画面だけへ入力し、着信やロック画面上の別アプリなどが前面なら拒否します。Android 12はスワイプ・認証なしのロック解除だけに対応します。
- スマホ操作ヘルパーとユーザー補助が使えることが必要です。メーカーによっては、USBデバッグでの入力を許可する追加設定が必要です。
- 認証情報はスマホ内に暗号化して保存し、モデル・PC・ログへ送りません。これらのツールは引数を受け付けません。
- 入力前に試行を記録します。失敗、時間切れ、停止、プロセス中断後は `attempt_blocked` となり、本人がスマホで値を確認して保存し直すまで再試行できません。許可の切り替えやアプリの再起動では解除されません。
- `disabled` は未許可、`helper_unavailable` はヘルパー未接続、`credential_required` は保存が必要、`unlock_failed` は解除を確認できなかった状態です。入力コマンドの成功だけで解除成功とはしません。
- 再起動後、最初のロック解除は本人が行ってください。この機能はシステムのロック設定を変更せず、タスクの支払い・承認を代行しません。

## 接続時の制約

- 既定では無効で、有効な間だけ待ち受けます。無効にすると停止します。
- USBはスマホの `127.0.0.1` だけで待ち受け、ADBがPCへ転送します。スマホ内の別アプリもポートへ接続できるため、トークン認証は省略しません。USBトークンはスマホ自身からの接続でだけ受け付けます。
- USBアクセスを有効にするサービスは `INTERACT_ACROSS_USERS_FULL` を持つ呼出元だけを受け付けます。adb shellは持ちますが、通常のアプリへadbで付与できる権限ではありません。接続情報はMika JPの外部ファイルディレクトリへ保存します。
- すべての要求にトークンが必要です。トークンは32バイトの乱数で、比較時間が値に依存しない方法で確認します。同じアドレスから1分間に5回間違えると、1分間拒否します。
- `Origin` ヘッダー付きの要求を拒否し、通常のブラウザページから接続させません。
- 直接接続は端末自身・LAN・プライベートVPNに限定し、公開IPからは受け付けません。
- PCから渡したタスクでの支払い、必要な承認、本人への引き継ぎはスマホで対応します。自律モードでも `mika_answer` によって同意や決済を代行できません。
- PCからはリモートタスクだけを参照・停止できます。スマホ上で直接開始したタスクや会話へは参加できません。同じアクセス権限を持つリモートクライアント間では、CLIとMCPのタスクを共用します。
- 実行記録にはPCから始めたことを記録します。
- 直接接続はHTTPです。信頼できるネットワークで使い、漏えいが疑われた場合はスマホでトークンを更新してください。

## 接続できない場合

| 症状 | 対処 |
| --- | --- |
| アドレスが表示されない | スマホのWi-FiまたはプライベートVPN接続を確認します。 |
| 待受を開始できない | ポートが使用中の可能性があります。無効にしてから有効にし直します。 |
| USB起動ファイルがない | Mika JPを一度開き、少し待って再試行します。対応するフォークのAPKかも確認します。 |
| USBで接続拒否・切断になる | ADB転送を再実行します。スマホを再起動した場合は、先に起動スクリプトも再実行します。 |
| PCの8765が使用中 | `adb forward tcp:18765 tcp:8765` など、PC側だけ別の空きポートにし、URLも `http://127.0.0.1:18765/mcp` にします。 |
| HTTP 429 | 認証失敗が続いています。正しいトークンを確認して1分待ちます。USBではスマホ内の接続元が同じアドレスとして数えられます。 |
| ネットワークで接続できない | 同じプライベートネットワークか確認します。ゲストWi-Fiなどは端末間通信を禁止する場合があります。 |
| 開始要求が失敗する・2分後にfailedになる | スマホでMika JPを開き、背景起動が制限されていないか確認します。元の要求が始まったかを確認してから再試行します。 |
| pausedのまま | スマホを本人がロック解除します。遠隔解除を許可済みなら、その結果のunlockedとreadyを確認します。点灯だけでは解除になりません。 |
