# デスクトップチェック「ChatGPTでログイン」

を使用する前に、まずコンピューター (macOS) で OpenAI 側をクリアします。このチェックでは、アプリと同じコードのセットが使用されます。ログインは `core/src/main/kotlin/com/wangzan101/mika/core/chatgpt/`、モデル リストは `ModelCatalog`、呼び出しは `ResponsesModel` です。入口は`core/src/chatgptCheck/`にあり、アプリには入りません。

## コマンド

はウェアハウスのルート ディレクトリにあります。

```
./gradlew :core:chatgptSignInCheck
```

オプションのパラメータ:

- `-Ptimeout=<秒>`: ブラウザーがコールバックするまでの待ち時間。デフォルトは 300 (5 分)。
- `-Pmodel=<slug>`: 使用するモデルを指定します。書かれていない場合は、リストから最初の推論モデルを選択します (書かれていない場合は、最初の推論モデルを選択します)。
- `-Pkeep`: 完了したらログインを保存します (下記の「プライバシー」を参照)。

## はどうなりますか

1. `~/.mika-dev/chatgpt-check/` にディレクトリ (権限 0700) を作成し、ローカル マシン ID と登録された client_id をそこの host.json に記録します。再度実行し、アプリと同じ登録を使用します。最初の実行では、新しいクライアントが登録されます。
2. は、127.0.0.1 でコールバック監視をオンにし、承認されたアドレスを出力し、デフォルトのブラウザで開きます (開けない場合は、アドレスを自分でコピーします)。
3. ブラウザで ChatGPT アカウントにログインし、承認に同意します。端末には、コールバックの受信、トークン交換、ID トークンの検証、付与された `chatgpt.tokens.use.direct`、付与された権限、電子メール アドレス、トークンの有効期間が順番に表示されます。
4. モデル (スラッグと表示名) をリストします。
5. モデルを使用して「単一の単語で応答:ポン」を 1 回送信し、応答と投与量を出力します。
6. ツール呼び出しラウンドトリップ: モデルは `get_time` を呼び出し、結果を function_call_output として返し、最終的な応答を出力します。また、通話に暗号化と再生があるかどうかも示します (store: false)。
7. リフレッシュ トークンを使用して新しいトークンに交換します。
8. 最後は概要です。各ステップは ✓ または ✗ ですが、場合によっては ✗ プロセスがゼロ以外で終了します (Gradle は BUILD FAILED と表示します。上の概要を見てください)。

一般的なエラーでは成人向けの言葉が使用されます。例: `subscription_sharing_user_not_eligible` (アカウント パッケージ、リージョンでは他のアプリでのクォータの使用が許可されていません)、`usage_limit_exceeded` (制限が上限に達しました)、`unsupported_capability` (リクエスト内のどのアイテムが書き出されます)、`access_denied` (認証ページでキャンセル)、client_id は不一致 (host.json を削除)、内部の clientId が再度一致します)。

起動が正常かどうかだけを確認したい場合は、`-Ptimeout=5`: 認証アドレスを出力し、ブラウザを開いて 5 秒でタイムアウトします。

## プライバシー

- アクセストークン、リフレッシュトークン、認可コード、IDトークンは出力されません。許可されたアドレスに ID トークンがありません。
- デフォルトのトークンはこの実行のメモリ内にのみ存在し、プロセスが終了すると失われます。
- と `-Pkeep` は `~/.mika-dev/chatgpt-check/session.json` に書き込まれます (許可 0600)。次回実行するときは、その中の電子メール アドレスをログイン プロンプトとしてのみ使用してください。このファイルが不要になった場合は削除してください。
- これらのファイルはウェアハウスではなく、ホーム ディレクトリにあります。
