# PCでChatGPTログインを確認する

アプリと共通のコードを使い、ChatGPTのログインとAPI接続をPCで確認する開発用ツールです。ログインは `core/src/main/kotlin/com/wangzan101/mika/core/chatgpt/`、モデル一覧は `ModelCatalog`、呼び出しは `ResponsesModel` を使います。入口は `core/src/chatgptCheck/` にあり、APKには含めません。実際のログインとモデル呼び出しを行うため、本人がブラウザーで認証し、アカウントの利用条件・利用枠を確認したうえで実行します。

## コマンド

リポジトリのルートで実行します。

```sh
./gradlew :core:chatgptSignInCheck
```

| パラメーター | 内容 |
|---|---|
| `-Ptimeout=<秒>` | ブラウザーのコールバックを待つ時間。既定は300秒 |
| `-Pmodel=<slug>` | 使用するモデル。省略時は利用可能な推論・ツール対応モデルを優先し、なければ最初の利用可能なモデル |
| `-Pkeep` | 終了時にログイン情報をローカルへ保存 |

## 確認する処理

1. `~/.mika-dev/chatgpt-check/` を作り、端末IDと登録済みclient_idを `host.json` に保存します。次回も同じ登録を使います。
2. `127.0.0.1` でコールバックを待ち受け、認可URLを表示して既定のブラウザーで開きます。開けない場合はURLを手動で開きます。
3. 本人がChatGPTへログインし、認可に同意します。コールバック、トークン交換、IDトークン検証、`chatgpt.tokens.use.direct` などの権限、メールアドレス、有効期間を順に確認します。
4. モデルのslugと表示名を列挙し、短い応答を1回要求して、結果と使用量を表示します。
5. `get_time` のツール呼び出しと `function_call_output` の返却を経て、最終回答を確認します。`store: false` の呼び出しで暗号化された推論内容を次の要求へ渡せるかも確認します。
6. リフレッシュトークンで更新を試し、各段階の成功・失敗を表示します。失敗があれば終了コードは0以外になり、Gradleにも失敗として表示されます。

代表的なエラーは、利用条件に合わない `subscription_sharing_user_not_eligible`、利用上限の `usage_limit_exceeded`、未対応機能の `unsupported_capability`、本人が認可を取り消した `access_denied` です。client_idの不一致ではローカルの登録情報を確認します。表示されたエラーを確認し、別のモデルを試す場合は `-Pmodel` を明示します。

起動経路だけを見る場合は `-Ptimeout=5` を指定できます。ブラウザーを開き、5秒後にコールバック待機がタイムアウトします。この結果だけでログインやモデル呼び出しの成功とは扱いません。

## 保存とプライバシー

- アクセストークン、リフレッシュトークン、認可コード、IDトークンは出力しません。認可URLにIDトークンは含めません。
- 既定ではトークンをメモリ内だけに保持し、プロセス終了時に破棄します。
- `-Pkeep` を指定した場合は `~/.mika-dev/chatgpt-check/session.json` に保存します。次回は保存されたメールアドレスをログイン時のヒントとして使います。不要な保存情報は利用者が削除します。
- POSIX権限に対応した環境では、ディレクトリは0700、保存セッションは0600に制限します。ファイルはリポジトリではなく利用者のホームディレクトリに置きます。
