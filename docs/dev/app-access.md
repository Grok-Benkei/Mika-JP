# アプリケーション アクセス (プロトタイプ バージョン)

設定 → アプリアクセス制御 パッケージ名別のミカ標準モバイルツール。新しいアプリケーションと権限のないアプリケーションは、金融アプリケーションを含め、デフォルトで許可されます。 AI はアプリケーションの主な目的に従って分類されます。分類および分類の失敗によって権限は変更されません。推奨される無効化は、ユーザーが特定のリストを適用した後にのみ有効になり、将来インストールされる同様のアプリケーションを自動的に無効にすることはありません。同じパッケージ名のクローンと作業データのコピーの共有ルール。

が無効の場合、標準モバイルツールは自動読み取りと操作を拒否し、`app_blocked` を返します。タスクの実行中に権限を変更すると、後続の呼び出しにも影響します。 `app_blocked` を受信した後、モデルは最初にルートを再評価します。他のアプリケーションがあり、ターゲットまたは Web ページのパスを共有している場合は続行します。対象のアプリケーションを使用する必要がある場合は、そのアプリケーションが「設定 › アプリケーション アクセス」で無効になっていることをユーザーに説明し、元のエラー コードで終了することなく自分で許可できることを説明します。回答とエラーの説明は、ユーザー メッセージの言語に従います。ブロック リストが空の場合、パッケージ名が欠落しているために拒否されることはありません。リストが空ではなく、所有権を確認できない場合は、少し待ってから再度リストを読み直してください。ターゲットの所有権がまだ確認されていない場合は、`app_access_unverified` が返され、権限は変更されません。権限ファイルが破損している場合、`app_access_unavailable` が返されますが、設定で明示的にリセットできます。認証に依存するインターフェイスは `app_access_protected` を返し、操作はユーザーに任されます。

アプリケーション アクセス ページを開くと、ローカル アプリケーション リストを読み取るだけで、コンテンツはモデルに送信されません。 [アプリケーション リストを更新] をクリックしても未分類のアプリケーションが残っている場合は、まずアプリケーション名とパッケージ名がリスク分類のために構成された AI モデルに送信されることを確認します。アプリケーション内のコンテンツは送信されません。まだ許可されており、1 つずつまたは一度にすべてを無効にできる金融アプリケーションのみを無効にすることをお勧めします。すでに無効になっているアプリケーションは再び表示されません。

ページのコピーはインターフェイス言語に従います。分類名はインターフェイスによって提供され、コアには中国語は含まれません。分類理由はインターフェース言語で記述されます。言語を変更した後も、古い理由はそのまま残り、次回再分類されたときに更新されます。手動で変更されたカテゴリは AI によって上書きされず、インターフェイスには「ユーザー選択」/「自分で設定」として表示されます。

ユーザーが無効化されたアプリケーション画面をアクティブに共有する場合、次のことを選択できます。

- **画面共有のみを許可**: 将来的にはアプリケーション画面を積極的に共有できますが、自動読み取りと操作は依然として禁止されています。アプリケーション アクセス ページで取り消すことができます。
- **このアプリケーションを許可**: 通常の通話を再開し、この共有を継続します。
- **共有のキャンセル**: 収集、共有、権限の変更はありません。

は、同じ画面上で写真とテキストを積極的に共有します。収集前にソースを確認し、収集後および送信前に許可を確認します。複数のウィンドウで、関連するすべてのアプリケーションをカバーする必要があります。このアプリケーションを許可すると独立した共有権限がクリアされ、再度無効にすると再認証が必要になります。

リストが空の場合、アプリケーション アクセスは追加の処理を行いません。ウィンドウはチェックされず、アプリケーション アクセス ルールはシステム プロンプトに追加されません。リストが空でない場合、スクリーン読み取りにはスクリーン読み取りのウィンドウ所有権が使用されます。ウィンドウが変化しない場合、その後の読み取りには以前の検証結果が使用されます (最大 1 秒)。

`wait` やその他のタスクでアプリを開くときは、待機する前にターゲットを確認します。無効化されたアプリケーションは、待機せずにその場で `app_blocked` を返します。待機は占有登録を見るだけで、画面を読み取らず、窓口認証も行いません。

## プロトタイプ境界

この機能は標準のモバイル ツールのみを制限します。シェル コマンド、サンドボックス、およびコンピューター アクセス (MCP) は、このアクセス制御によって制限されません。すべての Android シェルおよび Linux コマンドは、既存の機能と CommandSteer の動作を保持します。標準の電話ツールを介して呼び出された場合でも、スクリプトはゲートされます。このリリースでは、任意のコマンド自体と同じ UID によるファイル アクセスは分離されていないため、アプリケーション アクセス ルールでこれらのパス バイパスを保護することはできません。プロンプトの言葉は、AI が無効化の決定を尊重することを要求しますが、シェルの強制的なブロックは要求しません。

サードパーティ製アプリケーションは引き続き禁止されたアプリケーションを起動する可能性があります。パッケージ名チェックにより、標準ツールのフォローアップが妨げられ、Android に送信された入力を元に戻すことはできず、チェックと入力の間で競合状態がゼロになることは保証されません。すでにモデルに送信された履歴とコンテンツは遡って削除されません。アプリケーションのアンインストールおよび再インストール時に ID 依存関係リストを更新しても、ID の分離は保証されません。
