# アプリのアクセス

「設定 › アプリのアクセス」で、Mikaの標準スマホ操作ツールが利用できるアプリをパッケージ名ごとに設定します。新規・未分類のアプリは、金融アプリを含めて既定では許可されます。AIの分類は一覧整理と提案用で、分類結果や分類失敗によって権限は変わりません。無効化はユーザーが具体的な一覧へ適用した時点で有効になり、後から入れた同分類のアプリには自動適用されません。同じパッケージ名の複製アプリや仕事用プロファイルにも同じルールを使います。

## 無効化したアプリの扱い

標準ツールによる自動読み取り・操作を拒否し、`app_blocked` を返します。権限はタスク開始時に固定せず、実行中の変更も後続の呼び出しへ反映します。モデルは再試行・再読み取り、シェルや別アプリを使った制限回避を行いません。目的を達成できる別の許可されたアプリ・画面・共有先・ウェブ経路がある場合は、その方法を検討します。対象アプリが必須なら停止し、「設定 › アプリのアクセス」で無効になっており、そこで許可できることを日本語で説明します。

ブロック一覧が空なら、パッケージ名が不明なだけでは拒否しません。一覧が空でなく画面の所有元が分からない場合は、少し待って読み直し、それでも確認できなければ `app_access_unverified` を返します。設定ファイルが読めない場合は `app_access_unavailable` とし、設定画面での修復・明示的なリセットを案内します。認証や画面共有の保護画面は `app_access_protected` とし、ユーザー本人へ引き継ぎます。

## 分類と提案

ページを開くだけではローカルのアプリ一覧を読み、モデルには送りません。「アプリ一覧を更新」で未分類のアプリがある場合は、アプリ名とパッケージ名を設定済みのAIへ送ることを事前に確認します。アプリ内のコンテンツは送りません。まだ許可されている金融アプリについて無効化を提案し、個別またはまとめて適用できます。既に無効なアプリは提案しません。

表示名、分類理由、回答、エラー説明は日本語です。分類理由に明らかな外国語が返った場合は、日本語の理由を得られなかったことを示す案内へ置き換え、分類値やパッケージ名は保持します。手動で設定した分類はAIが上書きせず、「ユーザー選択」などの表示で区別します。

## ユーザーが画面を共有する場合

無効化したアプリの画面をユーザーが明示的に共有するときは、次を選べます。

- **画面共有のみを許可**: 以後の明示的な共有を許可します。自動読み取り・操作は引き続き禁止され、共有許可はアクセス設定で取り消せます。
- **このアプリを許可**: 通常の読み取り・操作を許可し、今回の共有も続けます。
- **共有をキャンセル**: 収集・共有・権限変更を行いません。

写真とテキストの共有は同じ権限確認を使います。収集前に画面の所有元を確認し、収集後と送信前にも許可を確認します。複数ウィンドウでは関係するすべてのアプリを対象にします。アプリ全体を許可すると独立した共有許可を消し、再度無効化した場合は共有の許可も取り直します。

ブロック一覧が空なら、追加のウィンドウ確認やアクセス規則のプロンプト追加は行いません。一覧がある場合は、画面の所有元を確認します。ウィンドウに変化がなければ、確認結果を最大1秒間再利用します。他タスクによる占有を待つ場合も、待機前に対象アプリを確認し、無効なら直ちに `app_blocked` を返します。占有待機そのものは画面の読み取りや所有元の検証を行いません。

## 制限の範囲

この機能が実行時に制限するのは標準のスマホ操作ツールです。シェルコマンド、サンドボックス、PCアクセス（MCP）全体を隔離する機能ではありません。AndroidシェルとLinuxコマンドには既存の機能・CommandSteerの規則が適用され、標準スマホツールを経由した操作にはアクセス確認が働きます。任意コマンドや同一UIDによるファイルアクセスの隔離は行いません。モデルにはユーザーの無効化を尊重させますが、OS全体でのアクセス遮断を保証しません。

別アプリが無効化したアプリを開く可能性もあります。標準ツールは後続の処理を拒否しますが、Androidへ送信済みの入力は取り消せず、確認と入力の間の競合も完全には防げません。モデルへ既に送った履歴や内容を遡って削除する機能はありません。アンインストール・再インストール後も、同じパッケージ名のアプリを別の主体として隔離するものではありません。
