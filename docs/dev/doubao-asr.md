# Beanbao ストリーミング音声認識 2.0

## の入り口と構成

設定 › モデル › Speech-to-Text の "Speaking and Converting Voice Service" には、"Beanbao ストリーミング音声認識モデル 2.0" の 1 行のみがあります。資格情報が保存されていない場合、タイムマークは "未設定" となり、別の設定ページ (`app/ui/SpeechModelScreen.kt`) をクリックします。保存後、円をクリックして選択し、右側の「設定」に移動して資格情報を変更したり、請求方法を変更したり、削除したりできます。設定ページの上部で、新しいバージョンのコンソール (音声サービス API キー) と古いバージョンのコンソール (アプリ ID + アクセス トークン) を切り替えます。請求方法として、時間単位バージョン `volc.seedasr.sauc.duration` または同時バージョン `volc.seedasr.sauc.concurrent` を選択します。最初に対応するサービスをアクティブ化するにはアカウントが必要です。請求方法のみを変更し、認証情報を再入力しない場合は、既存の認証情報が使用されます。 Ark チャット サービス プロバイダー、チャット モデル リスト、およびその資格情報は、このプロセスには関与しません。

は、ローカル マシン上の暗号化されたストレージにのみ保存され、オンライン サービスを呼び出しず、構成に検証済みのマークを付けません。マイクを長押しして接続を確立し、音声を送信します。サービス料が適用される場合があります。認証情報は個別に削除できます。現在使用されている Beanbao 資格情報を削除すると、音声入力がオフになります。システムは既存の音声セグメント全体を認識して転写し、独自のパスを維持し、自動的に有料サービスに切り替わることはありません。

認証情報は、既存の `KeyCipher` / Android キーストア スタンドアロン エイリアスを使用して暗号化されます。リソース ID のみを含む JSON を選択します。入力ボックスはキーをバックフィルせず、永続的な Compose 状態を使用しません。診断ではエンジン ID とリソース ID のみが記録されます。認証情報や音声コンテンツが誤ってエコーされることを避けるために、サーバー側のエラー メッセージは直接表示されません。

## リアルタイム パス

`SpeechChoice.Doubao` → `SpeechResolver` → `VoiceInput` → `DoubaoSpeech`。チャット入力とフローティングカプセルは同じ入り口を共有します。

- `PcmRecorder(streaming = true)` は、16 kHz、モノラル、PCM16 サンプリングをリアルタイムで提供し、元の非ストリーミング モードでも録音全体を返すことができます。
- `DoubaoTransport` は、スタンドアロン OkHttp WebSocket クライアントを使用して `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async` に接続します。資格情報は、固定された公式エンドポイントにのみ送信されます。本番クライアントはリダイレクトに従いません。
- はハンドシェイク後に gzip JSON 初期化を送信し、サーバーからの最初の確認を待ってから音声を送信します。 50 ms のサンプル ブロックが 200 ms のオーディオ パケットに結合されます。バッファリングされたオーディオも 200 ミリ秒間隔で送信されます。 PCM はリトル エンディアンを使用し、プロトコル長とオプションのシーケンス番号はビッグ エンディアンを使用します。
- 音声の送信と結果の受信は並行して行われます。 `result_type=full` をリクエストします。各 `Partial` は、重複を引き起こすスプライスなしで、以前の全文をカバーします。 `definite` は句安定性フラグであり、セッション全体の終了条件として使用することはできません。
- は解放されると録音を停止し、キューに入れられたサンプルを保持し、最後のパケット (フラグ 2、200 ミリ秒未満のテール トーンを含む、または空の最終パケット) を送信し、サーバーの最終フラグ/負のシーケンス番号を待ち続けてから、`Final` を送信します。最終パケットを受信せずに切断すると失敗となり、不完全なテキストは最終結果とみなされません。
- キャンセルによりイベント、オーディオ ストリーム、接続が閉じられ、遅延結果が抑制されます。記録は自動的に終了し、最後のパケットも送信されます。ハンドシェイク/初期化時間はそれぞれ 10 秒、最後のパケット送信後の待機時間は最大 10 秒、合計セッションは最大 75 秒です。元の UI の長押し録音制限は依然として 60 秒です。
- のオーディオキューは最大約 5 秒、ネットワーク送信キューと応答キューにも上限があります。上限を超えると失敗し、音を失うことなくマイクが解放されます。 gzip デコードされた応答は 1 MiB に制限されます。

は、デバイスの IMEI/MAC、履歴チャット、写真を送信しません。双方向インターフェイスは、サービスのデフォルトの認識機能に従って言語を処理し、一方向インターフェイスでのみサポートされる `audio.language` をシューホーンしません。

## の検証と制限事項

は、`DoubaoProtocolTest`、`DoubaoSpeechTest`、`DoubaoTransportTest`、および `DoubaoSettingsTest` を追加し、プロトコル サンプル、リアルタイム アップロード、全文置換、テール パケット、タイムアウト、キャンセル、2 世代のリクエスト ヘッダー、認証失敗、AES/GCM 資格情報の保存/回復/削除をカバーします。すべてのフィクスチャはモックと偽の認証情報をサンプルします。 WebSocket テストはネイティブ MockWebServer にのみ接続します。

通常の Android 開発環境は以下を実行できます。

```sh
./gradlew :app:testDebugUnitTest --tests 'com.wangzan101.mika.voice.*'
./gradlew :app:assembleDebug
```

実際の火山アカウントの権限、料金、遅延、正確性は、アカウントを持つ人によって検証される必要があります。アカウントをお持ちでない場合は、設定ページの確認、資格情報の保存と削除、および失敗時のプロンプトのみが可能です。
