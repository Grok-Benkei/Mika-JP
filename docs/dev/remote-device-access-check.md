# リモート画面操作の検証記録

記録日: 2026-10-31。上流のコミット `65e82c0d01ac0f016db76cde4c76cb9a3c03183c`（0.1.16）を基にした記録です。当時の開発用アプリでの結果を保持したもので、現在のMika JPや全Android機種で同じ確認を実施したという意味ではありません。Mika JPの確認範囲は[日本向け調整の記録](../JAPAN_TUNING.md)を参照してください。

## 実装の分担

- リモートの画面点灯・ロック解除は既定で無効です。認証情報はスマホのPC接続設定で本人が登録します。
- `core/device/DeviceAccess.kt` は準備処理を直列化し、実際の端末状態を確認します。入力と状態取得はAndroid実装が担います。
- `app/settings/DeviceAccessSettings.kt` は専用のKeystoreキーで暗号化し、アトミックに保存します。非機密状態だけを外へ出し、復号した認証情報をキャッシュしません。
- `McpDeviceTools` は状態確認・画面点灯・ロック解除を提供します。引数を受け付けず、既存のMCP認証を使います。モデル向けツール一覧やタスク履歴には含めません。
- `TaskGate` は実際のロック解除を確認して待機を解きます。メイン画面の端末操作とエージェントの仮想画面は別です。
- 設定画面は既存のグループ・行・ボタン・入力部品を使います。現在のMika JPでは日本語表示です。保存済みの秘密値を入力欄へ埋め戻さず、編集中はスクリーンショットを禁止します。

## 当時の自動検査

環境はJDK 17、Android SDK 36と、当時のリポジトリで固定したGradle・AGP・Kotlinです。

```sh
./gradlew :core:test :app:testDebugUnitTest \
  :app:assembleDebug :app:assembleDebugAndroidTest
```

記録された結果はcore 2416件、appのJVM 977件で失敗・エラーなし、coreの既存2件がスキップです。依存方向、ドキュメント、当時の文字列リソース、既存動作と追加機能を検査しています。この数値を今回の変更後の検査結果として再掲するものではありません。

追加対象は、既定無効、ヘルパーなし、再起動後の初回ロック解除、既に点灯した状態、コマンド成功後も画面が点灯しない場合、認証情報なし、PIN・パスワード、入力後の値の破棄、誤認証後の再試行停止、同時要求、キャンセル、待機中の手動解除・許可取り消し、暗号化保存と鍵の消失、認証情報更新による旧要求の失効、MCP認証・引数制限です。標準ロック画面の描画型PIN欄と、SIM・不明な入力欄を区別する回帰検査も含みます。

## 当時のAndroid 16実機

公開版とデータを残すため、アプリID `com.wangzan101.mika.dev` の別開発APKを使っています。これは現在のMika JPの `jp.studioyebisu.mika` とは異なります。USB MCPも別ポート18765を使い、元のモデルキーや個人データはコピーしていません。

本人が実際のロック画面の認証情報をスマホ上で登録し、検査スクリプトは読み取り・出力を行っていません。記録に残すのは次の非機密状態です。

| 段階 | `interactive` | `keyguardShowing` | `deviceLocked` | `ready` |
|---|---|---|---|---|
| 開始時 | true | false | false | true |
| 消灯・ロック後 | false | true | true | false |
| リモートの画面点灯後 | true | true | true | false |
| PINによるリモート解除後 | true | false | false | true |

入力前の占有記録と成功後の解除も確認し、状態の読み取りだけでなく認証情報の入力経路を通ったことを確かめています。

標準ロック画面の `pinEntry` は、編集可能と宣言されない描画型の `com.android.keyguard.PasswordTextView` です。ID、クラス名、パスワード属性を組み合わせて認識します。それ以外はパスワード属性と入力種別が一致する編集欄だけを対象にし、座標の推測や画面の文字による入力先の決め打ちは行いません。

`DeviceAccessSectionTest` は確認用の架空データで、二重入力による照合、保存条件、秘密値を再表示しないことを検査しています。最初は検査画面が前面に出なかったため、開発版を前面にして再実行し、1件成功した記録です。実際の保存認証情報は変更していません。

## 未確認の範囲

- 実機のロック方式は変更せず、既存PINを使用しています。パスワードなし・スワイプ・パスワードの各方式は自動検査だけで、実機を切り替えて確認していません。
- 対応する入力は4〜16桁のPIN、4〜64文字の印字可能ASCIIパスワードです。パターン、SIM PIN、不明なメーカー独自画面には対応しません。
- 再起動後、本人が初回ロック解除する前のMCP起動は対象外です。
- この実機記録は、認証キーの入力先をSystemUIのウィンドウに限定する変更（`ShellService.injectTo`）より前です。変更後のPIN解除と、別ウィンドウが重なったときに入力せず `input_failed` となることは、別の実機確認が必要です。
- わざと誤ったPINを実機へ送っていません。誤認証後の再試行停止は自動検査で確認しています。
- 支払い・承認の方針は変更せず、この検査のための外部アプリ操作やモデルの再設定も行っていません。

現在の利用手順は[MCP接続](../mcp.md)を参照してください。
