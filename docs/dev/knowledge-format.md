# 内蔵知識とスキルの形式

内蔵知識とスキルは、`core/src/main/resources/` の `knowledge/apps/`、`knowledge/sites/`、`skills/` に置き、アプリとともに配布します。ユーザー個人のスキルは、Mikaが端末上での学習によって作成します。アプリについて学んだ補足は、事実だけを箇条書きにし、内蔵の `APP.md` に追記してモデルへ渡します。実行方法や許可の規則とは分けて扱います。仕組みは[アーキテクチャ](architecture.md)の「知識とスキル」を参照してください。

| ファイル | 書く内容 | 書かない内容 |
|---|---|---|
| `knowledge/apps/<id>/APP.md` | アプリの用途、画面構成、機能、取得できる情報 | 共通の行動規則、作業全体の進め方 |
| `knowledge/sites/<ドメイン>/SITE.md` | サイトの用途、ページとURLの構造、機能、公開インターフェイス | 共通の行動規則、作業全体の進め方 |
| `skills/<id>/SKILL.md` | アプリやサイトをまたいで再利用できる作業の進め方 | 業種・商品分類だけで分けた専門業務の説明 |

## 共通要件

- アプリ・サイトの知識には、確認できた事実を書きます。承認、確認、停止などの共通規則は、既存の方針や実行層に任せます。
- モデルがそのまま利用できる自然な日本語にします。「このバッチ」「一般条項」「範囲・停止・機能」など、内部の整理用語を並べません。
- スキルからアプリ・サイトの知識を参照できます（`app:<id>`、`site:<ドメイン>`）。アプリ・サイトの説明から特定スキルの使用を指示しません。
- 現象と指示を区別します。例えば「下のタブを押さない」ではなく、「ホームの項目と下のタブには同名の入口があり、それぞれ遷移先が異なる」と記述します。
- 画面は「画面」「ページ」「入口」「ボタン」など、実際の対象が分かる語で説明します。
- 本文は2500文字以内にします。コード表、URL形式、検索構文などの大きな資料は `references/` に分け、いつ読む資料かを本文に示します。
- パッケージ名、ドメイン、URL、APIのアドレス、フィールド名は正確に保ちます。確かめられていない画面経路や値は作りません。

## APP.md

以下は書式の例です。機能や画面の説明は、対象アプリで実際に確かめた内容へ置き換えます。

```markdown
---
name: chrome                       # ディレクトリ名。英小文字・数字・ハイフン
display: Chrome
description: ウェブの閲覧、検索、タブの操作   # 用途を60文字以内で説明
packages: ["com.android.chrome"]
package_aliases: ["Chrome | com.android.chrome"] # 任意。呼び名とパッケージの対応
aliases: ["Chrome", "クローム"]
sites: []                          # 任意。対応するサイト知識の名前
open: Chrome                       # アプリを開くときに使う名前
pace: careful                      # 任意。操作速度に制限がある場合だけ指定
links: ["例のページ | https://example.com | com.android.chrome"] # 任意。確認済みの入口
---
## 概要
アプリの用途を1〜2文で説明する。複数パッケージがある場合は違いも記す。

## 画面構成
主な画面、下部タブ、検索入口、よく使う機能の位置を書く。

## 機能
- **機能名**: 入口、ログインの要否、表示される情報（価格・状態・項目など）。

## 確認済みの挙動
紛らわしい入口、よく出るダイアログ、読み込み・更新時の特徴。なければ省略する。
```

例の `pace` は任意フィールドの書式を示しています。Chromeなどに制限があると判断する根拠にはしません。

## SITE.md

```markdown
---
name: youtube.com                  # 主ドメイン
display: YouTube
description: 動画の説明、検索、チャンネル情報
domains: ["youtube.com", "youtu.be"]
aliases: ["YouTube", "ユーチューブ"]
apps: []                           # 任意。対応するアプリ知識の名前
open: youtube.com                  # 最初に開くアドレス
mode: desktop                      # desktop / mobile のどちらの画面を使うか
pace: careful                      # 任意。閲覧速度に制限がある場合だけ指定
links: []                          # 任意。確認済みの入口
---
## 概要

## ページとURL
主なページ、パラメーターを含むURL形式、検索入口。

## 機能
- **機能名**: ページ、ログインの要否、取得できる情報。

## 公開インターフェイス
任意。公開APIのアドレス、パラメーター、戻り値の形式。

## 確認済みの挙動
必要な場合だけ書く。
```

`pace` はサイトに関する事実であり、モデルへの規則ではない。指定可能な値は `careful` だけで、サイトが訪問者 1 人の閲覧速度を制限していることを示す（ページ送りや詳細表示が速すぎる、または多すぎるとブロックや認証要求が発生する）。未指定ならこの種の制限はない。`careful` を指定したサイトでは、Mika は同じサイト内のページ移動前に長めに待機する（約 10–22 秒。閲覧が増えるほど長くし、最大 30 秒）。1 タスクでそのサイトを閲覧できるページ数の上限も低くする（通常のサイトは 20 ページ、この種のサイトは 12 ページ。ユーザーが閲覧の続行に同意したら数え直す。閲覧だけを対象とし、そのサイトで送信や提出などの外部操作に一度でも成功した後は制限を設けない）。ビルド時に検証し、App とサイトには指定できるがスキルには指定できない。値が誤っていればビルドを失敗させる。

App の `pace` も同じく事実を表す。`careful` を指定した App は、1 アカウントの操作速度を制限する（タップが速すぎる、スクロールが多すぎると、ブロック、認証要求、場合によってはログアウトが発生する）。Mika はパッケージ名でその App を識別し（`packages` 内のいずれかに一致すれば該当）、各手順の前に長めに待機する（新しい画面では約 2.5–5 秒に、その画面の文字数に応じた読む時間を加え、最大 15 秒。同じ画面で続けて操作する場合は約 1–2 秒）。待機中にはときどき軽く下へスワイプし、文字入力も遅くする。1 タスクでその App の新しい画面へ移動できるのは最大 24 回（開く操作と戻る操作をそれぞれ 1 回と数え、同じページを下へスクロールして読む操作は数えない。ユーザーが閲覧の続行に同意したら数え直す。送信や提出などの外部操作に一度でも成功した後は制限を設けない）。設定の操作テンポで「速い」を選んだ場合は、これらをすべて行わない。

サイトのディレクトリには `scripts/` を置ける。サイトコマンド（`/* mika-command` ヘッダー付きの .js）またはサンドボックススクリプト（`scripts/manifest.json` に記載）を格納する。

## SKILL.md

個人スキルの自動学習と同じ形式です。`prompts/roles/skill_draft.md` も参照してください。

```markdown
---
name: pdf-text
display: PDFの文字を抽出する
description: このスキルを使う場面を1文で説明
aliases: ["PDFを読む", "PDFをテキストにする"]
apps: []                           # 任意。利用するアプリ知識の名前
sites: []                          # 任意。利用するサイト知識の名前
---
## 開始条件
## 手順
## 注意点
## 完了の確認
## ユーザーに引き継ぐ条件
```

スキルは「この種の作業」の進め方を記述します。`references/` の添付資料と `scripts/` のスクリプトを含められます。

## メタデータの整理

実行時に利用しない `risk`、`status`、`updated`、`verified_on` は内蔵資料のヘッダーから除きます。`terms` はスキル用です。アプリ・サイトの別名には `aliases` を使います。

## エージェントによる読み取り

| ツール | 対象 | 引数 |
|---|---|---|
| `knowledge_search` | アプリ・サイトの知識。最大10件の `{name, display, kind, description}` | `query`、任意の `kind`（`app` / `site`） |
| `knowledge_read` | アプリ・サイトの知識または添付資料 | `name`（`app:<id>` / `site:<ドメイン>` も可）、任意の `file_path` |
| `skill_search` | 内蔵・個人スキル。最大10件 | `query` |
| `skill_read` | スキルまたは添付資料の全文 | `name`（`skill:<id>` / `personal:<id>` も可）、任意の `file_path` |

- アプリやサイトを開くと、その知識を自動でモデルへ渡します。`knowledge_read` は、添付資料や、まだ開いていない対象の知識を読む場合に使います。
- `knowledge_read` / `skill_read` の結果には、同梱スクリプトと `scriptSource` が含まれます。サンドボックスでは `run_bundled_script` の `source`、`script`、`args` を指定して実行します。詳しくは[同梱スクリプト](skill-scripts.md)を参照してください。
- サイトコマンドは `web_run_site_command` で実行します。`web_evaluate_js` と同じく読み取り専用です。
- 知識、スキル、プロンプトに書くツール名は、現在登録されているものに限ります。整合性はテストで確認します。
