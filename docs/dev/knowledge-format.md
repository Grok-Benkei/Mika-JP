# フォーマット

日本語の正本 | [同じ内容への旧リンク](knowledge-format.en.md)

の知識とスキルはアプリとともにリリースされ、`core/src/main/resources/` の下の `knowledge/apps/`、`knowledge/sites/`、および `skills/` に配置されます。ユーザー自身の個人的なスキルは、携帯電話での独習を通じてミカによって作成されます。アプリの知識は携帯電話での自習でも補うことができ、補足は事実のみのリスト（それぞれの「-」）であり、実践や規制ではなく事実だけを書き、内蔵のAPP.mdの裏面に添付します（`docs/dev/architecture.md`「知識とスキル」を参照）。

3 つのファイル。それぞれが 1 つの役割を果たします。

|ファイル |何があっても |何があっても |
|---|---|---|
| `knowledge/apps/<id>/APP.md` |このアプリは何なのか、インターフェースはどのように構成されているのか、どのような機能があるのか​​、何が見えるのか |行動規制・やり方 |
| `knowledge/sites/<主域名>/SITE.md` |この Web サイトは何なのか、ページと URL はどのように構成されているのか、どのような機能があるのか​​、パブリック インターフェース |行動規範、物事のやり方 |
| `skills/<id>/SKILL.md` |あるタイプのことを行う方法 (再利用可能な方法、複数のアプリ/Web サイトで使用可能) |特定の業界またはカテゴリーにおける専門的な業務 |

## の共通要件

- **事実のみを書いてください**。認可、確認、停止条件、「でっち上げてはいけない」「ユーザーに任せる」などの規定は、一般的な規格や承認レベルに属し、ナレッジには記載されていません。
- **ミカ自身の言葉で書かれています**。 「このバッチ」、「証拠」、「一般条項」、「チャネル」、「範囲/停止/機能」などの形式の単語は使用しないでください。
- **説明にはスキルが引用されていません**。スキルはアプリ/ウェブサイトで名前を付けることができます (`app:<id>`、`site:<域名>`)。アプリ/ウェブサイトの説明には「XX スキルを押してください」は表示されません。
- **現象は現象と書きます**。 「下ラベルをクリックしないでください」ではなく、「ホームページグリッドの『テイクアウト』と下ラベルの『テイクアウト』が二つの入り口です。前者がテイクアウトチャネルに入ります」。
- 画面については「画面」「ページ」「入口」「ボタン」と表現し、「画面を見る」とは書かない。
- 本文は 2500 文字以内とする。大きな資料（駅名コード表、URL 形式、検索構文）は `references/` に置き、いつどの添付資料を読むかを本文で明示する。
- パッケージ名、ドメイン、URL、API アドレス、フィールド名などの事実はそのまま保持する。確信のない事実は記載しない。

## APP.md

```markdown
---
name: bilibili                     # 目录名,小写字母数字连字符
display: 哔哩哔哩
description: 视频、直播与动态(不超过 60 字,说这个 App 能做什么)
packages: ["tv.danmaku.bili", "com.bilibili.app.in"]
package_aliases: ["国际版 | com.bilibili.app.in"]     # 可选:某个叫法对应哪个包
aliases: ["B站", "哔哩哔哩"]
sites: ["bilibili.com"]            # 可选:对应的网站知识
open: 哔哩哔哩                       # 打开 App 时用的名字
pace: careful                      # 可选:这个 App 限制操作快慢(操作太快、看得太多会被拦、要验证或退出登录)
links: ["首页 | bilibili://... | tv.danmaku.bili"]       # 可选
---
## 是什么
一两句:这个 App 提供什么服务,有几个独立的包时各是什么。

## 界面
主要页面、底部标签、搜索入口、常用功能在哪个位置。

## 功能
- **功能名**:从哪进去;要不要登录;能看到哪些信息(价格、状态、字段)。

## 已知现象
容易混的入口、常见弹窗、加载或刷新上的特点。没有就不写这一节。
```

## SITE.md

```markdown
---
name: bilibili.com                  # 主域名
display: 哔哩哔哩
description: 视频、搜索与用户主页
domains: ["bilibili.com", "b23.tv"]
aliases: ["B站", "bilibili"]
apps: ["bilibili"]                   # 可选:对应的 App 知识
open: bilibili.com                  # 打开时用的网址
mode: desktop                      # desktop / mobile:用哪种页面
pace: careful                      # 可选:这个网站限制浏览快慢(看得太快、太多会被拦)
links: ["..."]                     # 可选
---
## 是什么

## 页面与网址
主要页面、网址的写法(带参数的格式)、搜索入口。

## 功能
- **功能名**:在哪个页面;要不要登录;能看到哪些信息。

## 接口
可选:公开接口的地址、参数、返回格式。

## 已知现象
可选。
```

`pace` はサイトに関する事実であり、モデルへの規則ではない。指定可能な値は `careful` だけで、サイトが訪問者 1 人の閲覧速度を制限していることを示す（ページ送りや詳細表示が速すぎる、または多すぎるとブロックや認証要求が発生する）。未指定ならこの種の制限はない。`careful` を指定したサイトでは、Mika は同じサイト内のページ移動前に長めに待機する（約 10–22 秒。閲覧が増えるほど長くし、最大 30 秒）。1 タスクでそのサイトを閲覧できるページ数の上限も低くする（通常のサイトは 20 ページ、この種のサイトは 12 ページ。ユーザーが閲覧の続行に同意したら数え直す。閲覧だけを対象とし、そのサイトで送信や提出などの外部操作に一度でも成功した後は制限を設けない）。ビルド時に検証し、App とサイトには指定できるがスキルには指定できない。値が誤っていればビルドを失敗させる。

App の `pace` も同じく事実を表す。`careful` を指定した App は、1 アカウントの操作速度を制限する（タップが速すぎる、スクロールが多すぎると、ブロック、認証要求、場合によってはログアウトが発生する）。Mika はパッケージ名でその App を識別し（`packages` 内のいずれかに一致すれば該当）、各手順の前に長めに待機する（新しい画面では約 2.5–5 秒に、その画面の文字数に応じた読む時間を加え、最大 15 秒。同じ画面で続けて操作する場合は約 1–2 秒）。待機中にはときどき軽く下へスワイプし、文字入力も遅くする。1 タスクでその App の新しい画面へ移動できるのは最大 24 回（開く操作と戻る操作をそれぞれ 1 回と数え、同じページを下へスクロールして読む操作は数えない。ユーザーが閲覧の続行に同意したら数え直す。送信や提出などの外部操作に一度でも成功した後は制限を設けない）。設定の操作テンポで「速い」を選んだ場合は、これらをすべて行わない。

サイトのディレクトリには `scripts/` を置ける。サイトコマンド（`/* mika-command` ヘッダー付きの .js）またはサンドボックススクリプト（`scripts/manifest.json` に記載）を格納する。

## SKILL.md

自動学習で蓄積する個人スキルと同じ形式（`prompts/roles/skill_draft.md` を参照）:

```markdown
---
name: pdf-text
display: 取 PDF 文字
description: 一句话:什么情况下用这份技能
aliases: ["读 PDF", "PDF 转文字"]
apps: []                           # 可选:用到的 App 知识名
sites: []                          # 可选:用到的网站知识名
---
## 入口
## 步骤
## 容易出错的地方
## 怎样算办成(核实证据)
## 什么时候停下交给用户
```

スキルは業界や商品分類で分けず、「この種の作業」の進め方を書く。`references/` の添付資料と `scripts/` のスクリプトを含められる。

## ヘッダーフィールドの保持と削除

削除するもの:`risk`、`status`、`updated`、`verified_on`（実行時に使用しないメタデータ）。
`terms` はスキル専用とし、App とサイトには `aliases` を使う。

## Agent によるファイルの利用方法

知識（App、サイト）とスキルには、それぞれ「検索 / 読み取り」のツールの組がある:

| ツール | 検索対象 | 引数 |
|---|---|---|
| `knowledge_search` | App とサイトの知識、最大 10 件の `{name, display, kind, description}` | `query`;任意の `kind`（`app` / `site`） |
| `knowledge_read` |アプリまたは Web サイトのナレッジ、またはその添付ファイルを読む | `name` (`app:<id>`、`site:<域名>` として記述できます);オプションの `file_path` (`references/` のアタッチメント) |
| `skill_search` |スキル、内蔵スキル、個人スキルを合わせて最大10項目までチェック | `query` |
| `skill_read` |スキルまたはその添付ファイルの全文を読む | `name` (`skill:<id>`、個人スキル `personal:<id>` と書くことができます);オプションの `file_path` |

- がアプリまたは Web サイトに入ると、そのナレッジ テキストが自動的にモデルに与えられます。 `knowledge_read` は主に添付ファイルの読み取りや、まだ入力されていないアプリ/Web サイトの読み取りに使用されます。
- `knowledge_read`、`skill_read` 結果には、実行可能なスクリプトとその `scriptSource` がリストされます。サンドボックスで実行するには、`run_bundled_script` (`source`、`script`、`args`) を使用します。`docs/dev/skill-scripts.md` を参照してください。
- Web サイトの site コマンドは、`web_run_site_command` という名前で実行されます。これは、`web_evaluate_js` と同様に読み取り専用です。
- 知識、スキル、プロンプトワードに表示されるツール名は、現在登録されているツールである必要があり、テストで確認されます。
