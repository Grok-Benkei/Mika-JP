# ミカロードマップ

原則: **まず物事を完了し、次にスピードを追求し、次に機能を拡張します**。修復メカニズムは根本原因によって分類されており、個々のケースにパッチを適用するものではありません。現在の構造については、[`architecture.md`](architecture.md) を参照してください。

## 完成しました

- **セルフホスト リモート CLI/MCP**: モバイル アウトバウンド WSS、ワンタイム ペアリング、モバイル統合トークン認証、透過的な転送および切断セマンティクスを備えたシングル ユーザー、シングル デバイスの HTTPS ゲートウェイ。既存のタスクとデバイス機能を再利用します。デプロイメントについては、[remote-mcp.md](remote-mcp.md) を参照してください。パブリック ネットワーク証明書と特定のクライアントの間の互換性は、実際の展開で受け入れられる必要があります。

- **バックステージ仮想スクリーン管理アプリ**: 内蔵モバイル アシスタント (ワイヤレス デバッグ後、一度ペアリング)、仮想スクリーン、バリアフリー画面読み取りおよび操作、テキスト認識補助読み取り、引き継ぎ、携帯電話複合ツール (クエリ、連続コマンド、クロススクリーン コレクション、検索、抽出、ポップアップ ウィンドウ、待機、イベント、ジェスチャ、システム コマンド)。
- **内蔵ブラウザ**: プライベート仮想ディスプレイ上の WebView、DevTools プロトコル経由の実際の入力。デスクトップ ID、タブ プール、ログイン ステータスと「Web サイト ログイン」設定、Web ページの引き継ぎ、ダウンロードとアップロード、読み取り専用スクリプト。
- **Linux サンドボックス**: APK に付属する Alpine オペレーティング環境 (arm64)、セッションごとに 1 つのワークスペース、デフォルトでのネットワーク切断、ファイルの出入り、知識とスキルの組み込みスクリプト、およびサンドボックス内の携帯電話チューニング ツール。
- **ランタイム**: 実行と受信箱 (実行中に中断)、タスク センター (会話ごとに 1 回の実行、キューイング、さまざまな会話の並列化)、配信台帳、中断のマークと再起動後の通知、統合リソース調整、機能ごとのアセンブリ、サブタスク (読み取り専用リサーチ)。
- **メイン ループ**: 唯一の実行入口、属性によるツール レジストリとサービス、中心としての観察、ツールを調整せずに回答、`end_not_done`、システム生成ソース、回答後にバックグラウンドで結果を決定、一時的なモデル エラーに対する制限された再試行。ツール エンジンはインターフェイスの状態に直接依存しません (`PackageDependencyTest` が保持されます)。
- **コンテキスト**: キャッシュ パーティション、履歴は追加のみ、ほぼいっぱいの場合は 1 回圧縮、ユーザーの元の単語は切り取られることはなく、圧縮後に補充されます。
- **タイミングと条件付きトリガー**: 毎日および毎週の 1 回限り/固定間隔/現地時間、固定リマインダー、読み取り専用の条件チェックとステータス変更の重複排除、アイドル時の再実行、正確な目覚まし時計機能テスト、タイムゾーン変更後の再起動と再配置、結果は元のダイアログに戻り、計画ページ。ダイアログでのプランのクエリと管理は、このダイアログに限定されます。
- **記憶と学習**: 事実、好み、実践 (実践には承認が必要)、ユーザーのポートレート、暗号化されたストレージ。個人のスキルとアプリの知識のドラフトの起草 - 承認 - トライアル - 検証プロセス。
- **知識**: 組み込みアプリ、Web サイトの知識とスキル (`core/src/main/resources/` で、リストについては生成されたインデックスと README を参照)、統一フォーマット、2 組の検索/読み取りツール。
- **トークンの使用法**: 各モデル呼び出しはソース (サービス プロバイダー、モデル、目的) で計算され、マシンはそれを 400 日間 1 時間ごとに保存します。設定のページには、24 時間 / 7 日 / 30 日 / 90 日 / カスタマイズされた合計使用量、サービス プロバイダーごとに積み重ねられた傾向、サービス プロバイダーとモデルのランキングが表示されます。
- **リモート画面のオープンとロック解除**: コンピューター接続 (MCP) のある `mika_device_state` / `mika_wake_device` / `mika_unlock_device`、デフォルトではオフ、電話機でオンになり、PIN またはパスワードを保存します。資格情報は暗号化されてローカルに保存され、システムのロック画面インターフェイスにのみ送信されます。一度失敗すると一時停止され、再試行する前に電話機に再保存されます (アーキテクチャ §6 を参照)。
- **評価**: `eval/tasks/` に基づく実際のマシンの評価質問。チューニング プールと保持プールに分かれています。偽のモデルスクリプトとプロンプトワードのゴールデンサンプルテスト。

## 次へ

1. **実際のタスクを実行する実際のマシン**: 障害は根本原因に従って分類され、メカニズム レベルで修復され、同様のタスクがまとめて改善されます。
2. **検証と承認を再開します** (下記の「既知の問題」項目 1 を参照)。
3. **モバイル機能 v2**:
   - では、一度に複数のステップで待機条件を設定でき (テキストが表示されるまで待機し、次のステップを実行する前にページが静かになるまで待機します)、モデルのラウンドトリップを削減します。
   - 簡単な観察: 画面の読み取り結果は、前の画面との違いと短いインターフェイスの説明のみを送信します。
   - はオンデマンドでツールを提供します。最初はフィルタリングされたツール ディレクトリのみが提供され、必要に応じて完全な定義がロードされます。ツールの数が増加しても、固定プレフィックスは拡張されません。
   - は、同一モデル、同一タスクに基づくチャット収集の初回フィードバック時間、モデル往復回数、画面読み上げとアクション時間、完了率、読み逃しと重複を測定します。
4. **スケジュールされたタスクの後続段階**: ログイン状態のアプリでの状態監視。マルチステップのモニタリングとオーケストレーション。実行時間とタイムアウトのクリーンアップの上限。邪魔しない期間。連続失敗マージリマインダー;観測値による条件結果、「値が大幅に変化した場合のみ通知」および冷却。作成および編集中に次の数回プレビューします。ユーザーが明確に表明した長期的な意図に基づいた計画の提案 (ユーザーが提案を採用した場合にのみ有効になります)。
5. **その他のソースと機能**: チャネル (WeChat など。チャネル インターフェイス、所有者 ID、対応する質問番号は `core/run/` で定義されています)、トランスポート層、MCP サーバーとクライアントの設定入口。

## 既知の問題と一時停止

1. **開発段階では最終検証がオフになります** (ユーザーの決定: 開発段階は閉じられたままです)。 `TaskRun` の `reviewFinalAnswer = false`:
   - の回答はすべて「未検証」として記録されます。学習では、回答を提出した後の結果判定 (`LearnGate`、アーキテクチャ §3「結果判定」を参照) が検討され、検証は行われなくなるため、スキルドラフト、アプリの知識、経験ルート、トライアル移行は通常どおり発生します。認証が開かれた後も、合格しても不合格だった人は引き続きブロックされます。
   - リスクの承認は、グローバルな調査/自律性に基づいています (アーキテクチャ §4 を参照)。質問する場合、同意するためにお金を費やす 1 つのステップのみです。自律性が有効な場合、支払いはブロックされず、`autonomous` (`ConfirmDecision.judge` から始まる) の早期返却は、チェックする前に「間違った」ミカ「Do It Yourself」(`ownApp`) としてランク付けされるため、この保護層は自律モードでは有効になりません (ユーザーの決定: 現時点では変更しないでください。エージェントがミカ独自のインターフェイスを操作することで、ユーザーの操作を支援することもできます。後で決定します）。
2. **クラッシュ リカバリの保護が不完全**: 中断された操作の余波 (結果の返信、ユーザーへの通知、ダイアログでの「タスク中断」の記録) は `RunRecovery` (`app/task/RunRecovery.kt`) によって行われます。ユーザーはプロセスが強制終了された後にプロセスを開きます。アプリ (`MikaApp.onCreate`) は「中断」を受け取ります。タスク サービスが破棄されてもプロセスがまだ存在する場合 (`TaskService.onDestroy`)、その場で通知されます。通知されているかどうかは配送台帳をご確認ください。中断された各操作は 1 回だけ通知されます。 「異常な再起動が連続して発生した場合の補助サービスの停止」に対する保護はまだありません。途中からは実行を継続せず（画面状態は復元できません）、「中断→通知→ユーザー再起動」のみを行ってください。
3. **Web ページ読み取り専用スクリプトを実行する必要があります** (`core/cap/web/ReadScript.kt`、レビューのために提案されていますが、まだ完了していません):
   - は、読み取り専用環境が確立された後の変更を見てのみ、「秘密の入力ボックスであるかどうか」を判断します。それ以前にテキストに変更されたパスワードボックスは認識できません。 「以前はパスワード ボックスだった」マークアップをページ スクリプトと共有することを検討してください。
   - 「以前は秘密の入力ボックスでした」は、メインドキュメントの変更のみに焦点を当てています。同じソース iframe およびシャドウ ルート内でテキストに変更されたパスワード ボックスは認識できません。オートコンプリートで銀行カードでマークされた `<select>` は、選択された値を読み取ることができます。値がボックスのサイズを超える場合、scrollWidth とscrollHeight で長さまたは行数を確認できます。
   - シークレット テキストエリアのワード: isEqualNode は、そのテキスト ノードまたはそのテキスト ノードがページ上の既存のノードと同じかどうかを比較できます。ページがシークレット テキストエリアを含む出力に値を割り当てた後、defaultValue は割り当て前の単語を保持します。ページは、モデルが保持するテキスト ノードを別のシークレット テキストエリアに移動し (または、値「属性ノードをパスワード ボックスに移動」を配置し)、シークレットを書き込んで削除します。モデルが新しいボックスでそれを読み取らない場合でも、元のボックスに従って計算され、読み取ることができます。
4. **トリガーに小さなギャップ**: タイム ゾーンを変更した後、現地時間に従って繰り返されるプランは、次の請求まで新しいタイム ゾーンに従って再計算されません。
5. **クリップボード**: Web ページ編集領域は、入力の貼り付けに依存しています。 Android 12 以降、ホーム画面に「クリップボードにアクセスしています」というメッセージが短時間表示されます。確認コードや ID 番号などの機密テキストは、貼り付けると約 1 秒間クリップボードに残ります。テキストを送信するための入力方法としてミカを使用する必要性を完全に回避するため、大きな変更は延期されます。
6. **Web ページのタスクがエクスペリエンスの再生に入りません**: Web ページの動的コンテンツとログイン状態の違いにより、対戦で頻繁にエラーが発生します。まず携帯電話での再生を安定させてください。
7. **サードパーティのアカウント認証を必要とするスキル スクリプト** (クラウド ドキュメント、マップ インターフェイスなど) は当面は実行されません。これを行う場合は、サービス資格情報を安全に保存するための入り口が必要です。
8. **メモリはクラウド同期とエクスポートを行いません**。将来これを行う場合は、暗号化されたエクスポートを別途設計する必要があります。
9. **検証対象の実機**: 内蔵アシスタントのさまざまなシステム操作、アシスタントが強制終了またはワイヤレス デバッグがオフになった後の自動回復、再起動後の自動回復、長期間使用されなかった後の無効な認証での起動、Web ページのレンダリング プロセスのクラッシュ、Android 13 ～ 15 での正確な目覚まし時計の認証と非アクティブ化、およびロック画面中のスケジュールされたタスク。現状では単体テストとデバイステストが主で、実機上で逐次実行する必要もあります。
10. **評価用の取り消しできない質問**: デフォルトでは実行されません。実行するには、`-e evalAllowIrreversible true` を渡す必要があります。質問ごとに新しいダイアログを使用します。質問の送信と削除は実際に完了します (質問自体のマークされたデータとテスト アカウントのみが操作されます)。クエリモードで注文すると、確認カードで停止します（`EvalHooks`の自動応答を取得できます）。開発者向けオプションで自律性がオンになっている場合に注文を行う場合、そのようなセーフティ ネットはなく、注文は実際に行われます。
11. **後で**: コンピューターに接続し、タスク中に画面を暗くして電力を節約します。
12. **サスペンション カプセルの段階的な準備**: 最初のステップ (フローティング レイヤー ホスト、スイッチ、作業中 / あなたを必要としている / 処理中 / 終了したカプセル、引き継ぎと復帰、および通知との連携)、第 2 ステップ (カードをクリック: 小さな画面、ステップ、停止、引き継ぎ、同意 / 回答、結果、複数のリスト。境界線をドラッグ、1 つに縮小、場所を記憶)、第 3 ステップ (カードへの入力: 割り込み、応答する、チャットを続ける、最新の会話を続ける、または空いているときに新しい会話を開始する、入力方法がポップアップしたら邪魔にならないようにする）、第 4 のステップ（複数のこと: リストを優先度で並べ替える、カードを切り替える、実際の引き継ぎキューを次々に押す、次のアイテムは手渡した後すぐに「必要」になります）、第 5 のステップ（感触：タッチしないと数秒後に消えます、ステータス ポイントは 1 つに縮小しても固体のままです、など）入力メソッドがアプリにポップアップ表示される場合は、小さな部分に縮小して上部に移動し、画面を回転した後に比例して元に戻す必要があります)。それは行われました。フルスクリーンでプレイした際に自動で縮小するかどうか、カプセル上の単語を短文で追加するかどうかなど、各項目を実機で確認した上で確認を行った。
