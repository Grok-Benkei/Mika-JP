要素一覧で次の対象がすでに特定できる場合に、1回の呼び出しで同じ状態に対する連続した操作を実行する（例: 名前付きの欄をタップし、値全体を入力し、別の名前付きの欄をタップし、その値全体を入力する）。手順の数は、作業と既知の操作仕様から選び、1回あたりのリソース制限まで。各手順は次の手順の前にローカルで確認される。操作が失敗した場合、視覚的な確認が必要な場合、アプリが切り替わった場合、手順の待ち条件が満たされなかった場合に、まとめは止まる。手順が読み込みを開始し（検索、送信、ページを開く）、次の手順がその結果を必要とする場合は、待ちのためにまとめを終えず、その手順に条件を付ける。expect（表示される文面）、expect_gone（消える読み込みラベル）、expect_app（アプリのパッケージまたはページのアドレス）、wait_stable。その手順は timeout_s（既定8）まで待ち、ポップアップ、システムダイアログ、別のアプリで早期に止まる。結果には、どれだけ待ち、なぜ止まったかが示される。見て判断すべき手順（どの項目を選ぶか、うまくいったか）を超えてまとめない。そこでまとめを終える。状態が変わらないことだけでは、作業が止まったことにはならない。次に何をするかを決める前に、最後の状態を確認する。すべての手順は同じ状態に対して行われなければならない（そうでない場合は mixed_surface）。依頼された送信、投稿、注文、削除、支払いの操作をまとめに含めることができる。成功を主張する前に、結果の状態を読む。まとめの前に見えていて、同じ要素を今も指している ref だけを使う。対象が操作の後に初めて現れる場合は止め、新しい状態を確認する。
