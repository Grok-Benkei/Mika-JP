ユーザーだけができる手順（サインイン、確認パズル、支払い、その他手段では完了できない手順）のために、操作をユーザーに引き継ぐ。message に、ユーザーが正確に何をすべきかを示す。操作権が戻ったことは、その手順が成功したことの証明にはならない。outcome が complete の場合は、まず現在の状態を読み、結果を確認する（支払いなら注文の状態、サインインならサインインできているか）。確認できれば続行するか報告する。判断できない場合は、ask_user を呼び、例えば「完了した」/「完了していない、もう一度引き継いでほしい」/「中止する」などの選択肢（日本語）を示す。inputCount が 0 の場合でも確認する。ユーザーが別の方法で済ませた可能性がある。痕跡がまったく見られない場合にだけ、その手順は開始されていないものとして扱い、再度引き継ぐか質問する。durationMs で判断しない。確認せずに手順が成功したとは言わない。outcome が skipped または timeout の場合は、何も引き継がれていない。ユーザーが対応したとは主張せず、何が起きたかを伝え、別の方法を試すか作業を終える。ユーザーが操作権を返したら、作業を続ける。
